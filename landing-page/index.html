🏗️ Privacy-first architecture

Link checking that keeps your URLs private

Naively sending every URL to a server leaks your entire browsing history. ClickSafe uses a three-tier approach to avoid this.

1
Tier 1 · Instant
Whitelist check
If the domain is in your personal whitelist — safe, done. Nothing sent anywhere.
↓ no match
2
Tier 2 · Private · Local only
Local hash prefix store
The hovered URL is hashed (SHA-256) locally and checked against a 4-byte prefix store refreshed every 30 minutes. No match → safe, nothing leaves your browser.
↓ prefix match only
3
Tier 3 · Only on prefix match
Backend hash confirmation
Only the SHA-256 hash (not the URL) is sent to your backend, which calls Google Safe Browsing's fullHashes:find endpoint to confirm or deny the threat.
🏗️
Self-hosted backend required
Link checking and download scanning both require a Node.js/Express backend running locally or on your own server. The backend holds your Google Safe Browsing API key.
🍪
Cookie scanning runs entirely locally
The background service worker calls chrome.cookies.getAll() and classifies each cookie by domain against a known-tracker list. Nothing is transmitted.
📊
Privacy score formula (honest)
Score = 100 − 30 (if HTTP) − 5×tracking-cookies (max 30) − 4×tracker-scripts (max 20) − 5×mixed-content (max 20). Minimum 0.
🔄
Tracker blocklist stays fresh
On startup the extension loads a bundled seed list, then fetches the full live Disconnect.me services.json (~70k domains) from GitHub and caches it for 24 hours.
🔐 What "privacy-first" actually means

Most analysis stays on your device

HTTPS detection, tracker scanning, cookie analysis, mixed-content scanning, and dark pattern detection all run locally. Only link hover checking and download scanning touch a backend.

✓
All cookie & tracker scanning is local. Runs inside the extension's background service worker. No data leaves your browser.
✓
Dark pattern detection is local. Pure DOM/regex analysis; no page content is transmitted anywhere.
✓
Link checking sends only a hash prefix first. Raw URLs reach the backend only when a local prefix match needs confirming.
!
Download URLs do reach your backend. This is disclosed clearly — the backend needs to call Safe Browsing to verify a file's origin URL.
✓
You host the backend yourself. No third-party telemetry. Your Safe Browsing API key stays in your own .env file.

🚀 Installation

Get started in three steps

Requires Chrome, Brave, Edge, or any Chromium browser, plus Node.js for the backend.

1
Clone the repository
Download or clone the project from GitHub. You'll need the frontend/ folder for the extension and backend/ for the Node.js server.
git clone https://github.com/<your-repo>/clicksafe
2
Start the backend
Add your Google Safe Browsing API key to backend/.env and start the server. It runs on port 3000 by default.
cd backend && npm install && npm start
3
Load as unpacked extension
Go to chrome://extensions, enable Developer Mode, click "Load unpacked" and select the frontend/ directory.
chrome://extensions → Load unpacked → /frontend
❓ FAQ

Honest answers to real questions

No marketing language. Straight answers about what the extension does and doesn't do.

View on GitHub Read the Code
Most analysis — cookies, trackers, HTTPS, mixed content, dark patterns — runs entirely locally and nothing is transmitted. Download URLs are sent to your own self-hosted backend. Link hover checking uses local hash prefixes first; only the SHA-256 hash reaches the backend on a positive match.
Yes, for two features. Link hover checking and download scanning both call localhost:3000 (configurable). The extension gracefully handles the backend being unavailable — it resumes downloads and marks links as safe if the server is down.
Any Chromium-based browser: Chrome (v88+), Brave, Edge, Opera, Vivaldi, Arc, and similar. Firefox uses a different extension API and is not currently supported.
On startup the extension loads a bundled seed list (~178 priority trackers). It then fetches the live Disconnect.me services.json from GitHub and merges it (total ~70k domains). The live list is cached in chrome.storage for 24 hours.
Five categories: fake urgency, confirm-shaming, fake countdown timers, pre-ticked checkboxes for marketing, and cookie banner manipulation (an "Accept All" button with no visible "Reject" option).
The most expensive operation is the tracker scan, which runs Promise.all() across every script, image, and iframe on a page. On pages with many third-party resources this can add a few hundred milliseconds. Link checking is debounced to 300ms.
